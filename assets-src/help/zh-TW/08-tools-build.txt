建構：網站、應用程式、預覽和發布
## 如何詢問
- 「為我的咖啡店製作一個登陸頁面。」代理商會立即建立它，在您的手機上啟動它並在預覽中打開它。你會得到 2-3 行描述它的內容。除非您提出要求，否則不會發布任何內容。
- 「建立待辦事項應用程式。」直接使用合理的堆疊建置、運行並顯示。僅當您要求時才提供後端、資料庫或登入資訊。
- 「建立一個全端應用程式。」代理首先詢問一個關於後端語言、資料庫、登入及其運行位置的簡短問題，並使用建議的預設值，然後使用種子資料建立所有問題並測試一個完整的流程。
- 「製作一個Windows/Linux/macOS/Android程式。」編寫原始程式碼，添加建置工作流程，使用 GitHub Actions 將其推送並建立在雲端中，然後您將獲得真正的下載連結。

## 工具
- `edit_file` 和 `write_file`：寫入真實檔案（完整程式碼，從不存根）。 `code_box` 現場展示了他們。
- `preview`（安全）：內建真實瀏覽器。操作：開啟（連結、`localhost:PORT` 或檔案）、重新載入、後退、前進、螢幕截圖、捲動、點擊、鍵入、讀取頁面文字、控制台錯誤、評估。代理在表示完成前會先檢查自己的工作。
- `serve_local`（系統）：在手機上啟動資料夾的網路伺服器，並返回 Wi-Fi 上其他裝置可以開啟的 LAN 位址。
- `publish_website`（系統）：透過電話在公共連接埠上提供站點服務。 `publish_cloudflare`（系統）：透過 Cloudflare 隧道將沒有帳戶的網站放到網路上，並回傳公共 https 連結。 `publish_github`（系統）：使用您的令牌將項目發佈到 GitHub 儲存庫（頁）。
- `git`（系統）：克隆、初始化、狀態、新增、提交、推送、拉取、分支、結帳、日誌、與您儲存的令牌進行比較。 `github_pr`（系統）：建立、列出、合併和評論拉取請求。 `github_actions`（系統）：列出工作流程、運行它們、輪詢運行並讀取日誌，以便建置透過手機在雲端中運行。
- `build_app`（系統）：在手機上使用 Gradle 建置此項目並安裝結果。
- `files_panel`、`todo_write`：文件瀏覽器與任務板。

## 代理商遵循的品質規則
完整的佈局、響應式設計、有效的 JavaScript、動畫、一致的顏色和字體（適合的深色和淺色），而不是通用模板。登陸頁面通常有 300-900 行；更大的事情更多。

## 如果東西看起來壞了
按“預覽中的修復”，或告訴客服人員。它讀取控制台，修復原因，重新打開頁面並再次檢查。
