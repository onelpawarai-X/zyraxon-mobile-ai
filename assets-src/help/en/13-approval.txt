Approval levels and safety of automation
Settings → System → Automation. This decides how much the agent may do before it stops and asks you. The setting is enforced in code on every tool call; a model cannot widen it.

## The four levels
1. Full ask (Locked): asks before anything that changes the phone. Safest.
2. Supervised (default): asks before system and personal actions; does ordinary work by itself.
3. Balanced: asks only before system-level actions.
4. Full automation: never asks. Everything runs straight through.

## The three tiers of tools
- Safe (never asks at any level): reading and listing files, memory, documents, designs, status, opening apps and files, waiting, skills/autopilot/timeline/call lists, brain search.
- Personal (asked in the first two levels): SMS, calls, camera, screen reading, taps and typing, clipboard, downloads, notifications, sharing, voice change, skills replay, money ledger, call agent, timeline undo.
- System (asked at every level except Full automation): shell, Linux, builds, publishing, deleting, device lock, scheduling, Git and GitHub, ffmpeg, on-device model, posting to channels, autopilot rules, deleting skills, Shizuku. Any tool the app does not recognise — including MCP tools — is treated as System.

## The approval card
When a tool needs your approval a card says "Permission needed", tells you what the agent wants to do, shows its tier (Safe, Personal or System), and offers "Yes, run it" or "No, keep it off". The card also reminds you that you can change how often this is asked in Settings → Automation.

## On-device only
When on, nothing leaves the phone: only the on-device model and local tools run. All network tools (search, fetch, uploads, publishing, GitHub, media generation, MCP, cloud models) are refused in code.

## First launch notice
The first time, ZYRAXON explains that the agent can act on your phone and where to switch permissions on. Press "Got it, start".
