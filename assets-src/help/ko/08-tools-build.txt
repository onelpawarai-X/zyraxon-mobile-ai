구축: 사이트, 앱, 미리보기 및 게시
## 질문하는 방법
- "내 커피숍의 랜딩 페이지를 만들어 주세요." 에이전트가 즉시 빌드하고 휴대폰에서 시작한 후 미리보기에서 엽니다. 이를 설명하는 2~3줄의 내용이 표시됩니다. 요청하지 않는 한 아무것도 게시되지 않습니다.
- "할일관리 앱을 만들어 보세요." 합리적인 스택으로 직접 구축하고 실행하고 표시합니다. 요청하는 경우에만 백엔드, 데이터베이스 또는 로그인이 가능합니다.
- "풀스택 앱을 구축하세요." 에이전트는 먼저 권장 기본값을 사용하여 백엔드 언어, 데이터베이스, 로그인 및 실행 위치에 대해 간단한 질문을 한 다음 시드 데이터로 모든 항목을 빌드하고 하나의 전체 흐름을 테스트합니다.
- "Windows/ZYRAXON OS/macOS/Android 프로그램을 만드세요." 소스가 작성되고, 빌드 워크플로가 추가되고, GitHub 작업을 통해 클라우드에 푸시 및 빌드되고 실제 다운로드 링크가 제공됩니다.

## 도구
- `edit_file` 및 `write_file`: 실제 파일을 작성합니다(완전한 코드, 스텁 없음). `code_box` 라이브로 보여줍니다.
- `preview` (안전): 내장된 실제 브라우저입니다. 작업: 열기(링크, `localhost:PORT` 또는 파일), 다시 로드, 뒤로, 앞으로, 스크린샷, 스크롤, 클릭, 입력, 페이지 텍스트 읽기, 콘솔 오류, 평가. 에이전트는 작업이 완료되었다고 말하기 전에 자신의 작업을 살펴봅니다.
- `serve_local` (시스템): 휴대폰에서 폴더에 대한 웹 서버를 시작하고 Wi-Fi에 있는 다른 장치가 열 수 있는 LAN 주소를 반환합니다.
- `publish_website` (시스템): 전화기에서 공용 포트의 사이트를 제공합니다. `publish_cloudflare` (시스템): Cloudflare 터널을 통해 계정 없이 인터넷에 사이트를 배치하고 공개 https 링크를 반환합니다. `publish_github` (시스템): 토큰을 사용하여 프로젝트를 GitHub 저장소(페이지)에 게시합니다.
- `git` (시스템): 저장된 토큰을 사용하여 복제, 초기화, 상태, 추가, 커밋, 푸시, 풀, 분기, 체크아웃, 로그, 비교. `github_pr` (시스템): 풀 요청에 대한 생성, 나열, 병합 및 설명입니다. `github_actions` (시스템): 워크플로 나열, 실행, 폴링 실행 및 로그 읽기를 통해 휴대폰을 통해 클라우드에서 빌드가 실행됩니다.
- `build_app` (시스템): 휴대폰에서 Gradle을 사용하여 이 프로젝트를 빌드하고 결과를 설치합니다.
- `files_panel`, `todo_write`: 파일 브라우저 및 작업 보드.

## 상담원이 따르는 품질 규칙
일반적인 템플릿이 아닌 완전한 레이아웃, 반응형 디자인, 작동하는 JavaScript, 애니메이션, 일관된 색상 및 글꼴(어두운 부분과 밝은 부분)입니다. 랜딩 페이지는 일반적으로 300~900줄입니다. 더 큰 것들은 더.

## 뭔가 고장난 것 같으면
미리보기에서 수정을 누르거나 상담원에게 알립니다. 콘솔을 읽고 원인을 수정한 후 페이지를 다시 열고 다시 확인합니다.
