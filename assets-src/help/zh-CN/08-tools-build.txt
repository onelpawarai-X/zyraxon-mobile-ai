构建：网站、应用程序、预览和发布
## 如何询问
- “为我的咖啡店制作一个登陆页面。”代理会立即构建它，在您的手机上启动它并在预览中打开它。你会得到 2-3 行描述它的内容。除非您提出要求，否则不会发布任何内容。
- “构建一个待办事项应用程序。”直接使用合理的堆栈构建、运行并显示。仅当您要求时才提供后端、数据库或登录信息。
- “构建一个全栈应用程序。”代理首先询问一个关于后端语言、数据库、登录及其运行位置的简短问题，并使用推荐的默认值，然后使用种子数据构建所有问题并测试一个完整的流程。
- “制作一个Windows/Linux/macOS/Android程序。”编写源代码，添加构建工作流程，使用 GitHub Actions 将其推送并构建在云中，然后您将获得真正的下载链接。

## 工具
- `edit_file` 和 `write_file`：写入真实文件（完整代码，从不存根）。 `code_box` 现场展示了他们。
- `preview`（安全）：内置真实浏览器。操作：打开（链接、`localhost:PORT` 或文件）、重新加载、后退、前进、屏幕截图、滚动、单击、键入、读取页面文本、控制台错误、评估。代理在表示完成之前会先检查自己的工作。
- `serve_local`（系统）：在手机上启动文件夹的网络服务器，并返回 Wi-Fi 上其他设备可以打开的 LAN 地址。
- `publish_website`（系统）：通过电话在公共端口上提供站点服务。 `publish_cloudflare`（系统）：通过 Cloudflare 隧道将没有帐户的站点放到互联网上，并返回公共 https 链接。 `publish_github`（系统）：使用您的令牌将项目发布到 GitHub 存储库（页面）。
- `git`（系统）：克隆、初始化、状态、添加、提交、推送、拉取、分支、结帐、日志、与您保存的令牌进行比较。 `github_pr`（系统）：创建、列出、合并和评论拉取请求。 `github_actions`（系统）：列出工作流程、运行它们、轮询运行并读取日志，以便构建通过手机在云中运行。
- `build_app`（系统）：在手机上使用 Gradle 构建此项目并安装结果。
- `files_panel`、`todo_write`：文件浏览器和任务板。

## 代理商遵循的质量规则
完整的布局、响应式设计、有效的 JavaScript、动画、一致的颜色和字体（适合的深色和浅色），而不是通用模板。登陆页面通常有 300-900 行；更大的事情更多。

## 如果东西看起来坏了
按“预览中的修复”，或告诉客服人员。它读取控制台，修复原因，重新打开页面并再次检查。
