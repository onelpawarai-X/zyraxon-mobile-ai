クラウド、ネットワーク、モデル、ヘルパー
## クラウドとインターネット
- `web_search` (ネットワーク): 現実の Web を検索します。 `read_url` (ネットワーク): ページをテキストとして取得します。 `http_request` (ネットワーク): ヘッダーと本文を含む任意の HTTP 呼び出し (GET、POST、PUT、PATCH、DELETE)。 `verify_url` (ネットワーク): リンクが実際に存在することを確認し、真のステータスを取得します。 `download_file` (パーソナル、ネットワーク): URL をファイルにダウンロードします。
- エージェントは、ユーザーが要求した場合にのみリンクを開きます。
- AI モデルは、追加したプロバイダー (ZYRAXON、ZYRAXON Apex クラウド エージェント、Groq、Gemini、OpenAI、Grok、Claude、DeepSeek、OpenRouter、OpenCode) を通じてクラウドで実行されます。モデル リストはライブでロードされ、各プロバイダーが応答すると埋められます。
- ビルド、公開、プル リクエストは GitHub および Cloudflare (`publish_*`、`github_actions`、`github_pr`、`git`) を通じて実行されます。
- 「オンデバイスのみ」（自動設定）をオンにすると、クラウド呼び出しはまったく行われません。プロバイダー、Web、アップロードは行われません。

## MCP サーバー
MCP は、外部サービスがエージェントに追加のツールを提供します。 Canva、Cloudflare、Supabase、GitHub、または独自のサーバーをアドレス (オプションのトークン) で接続します。接続されたサーバーのツールは、エージェントのツール リストに `server__tool` として追加されます。
- `mcp_connect`、`mcp_disconnect`、`mcp_list` (何が接続されているか、どのツールが存在するかを確認します)、`mcp_resources`、`mcp_read_resource`、`mcp_prompts`、`mcp_prompt`、`mcp_subscribe` (リソースの変更を監視します)、`mcp_complete` (オートコンプリート引数)、`mcp_ping`、`mcp_log_level`。彼らの呼び出しはネットワーク呼び出しであり、不明な MCP ツールはデフォルトで許可を求めます。
- MCP 画面には、各サーバーの接続ステータス、そのツール、リソース、プロンプト テンプレート、および追加、切断、削除、許可のボタンがリストされます。

## サブエージェント
`sub_agent` (システム): バックグラウンドで実行されているヘルパー エージェントに大きなジョブの一部を渡します。アクション: 生成、ステータス、リスト、結果、メッセージ、停止、待機。それぞれが独自のモデルを使用できます。エージェントは、「完了」と言う前に、その結​​果を結合して確認します。

## オンデバイスモデル
`on_device_model` (システム): インターネットなしで電話上に存在する言語モデルをリストし、ロードし、実行します。設定 → モデルとアイデンティティ → デバイス上でモデルをダウンロードします (小さいものから大きいものまで: FunctionGemma 270M、Qwen3 0.6B、Gemma 4 E2B…)。 Hugging Face トークンはオプションであり、ゲートされたファイルにのみ必要です。ロードされたモデルは記憶され、起動時に再ロードされます。

## メッセージングチャネル
`channel_post` (システム) は、Telegram、WhatsApp、Facebook、Messenger、YouTube、X、Instagram、Gmail、または SMS を開き、テキストを準備します。自分で送信を押します。
