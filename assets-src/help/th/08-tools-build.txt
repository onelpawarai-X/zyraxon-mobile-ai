การสร้าง: ไซต์ แอป การแสดงตัวอย่าง และการเผยแพร่
## วิธีการถาม
- "สร้างแลนดิ้งเพจสำหรับร้านกาแฟของฉัน" เจ้าหน้าที่จะสร้างมันขึ้นมาทันที เริ่มมันบนโทรศัพท์ของคุณ และเปิดมันในหน้าตัวอย่าง คุณได้รับ 2–3 บรรทัดที่อธิบายมัน ไม่มีอะไรถูกเผยแพร่เว้นแต่คุณจะถาม
- "สร้างแอปสิ่งที่ต้องทำ" สร้างโดยตรงด้วยสแต็กที่สมเหตุสมผล เรียกใช้และแสดง แบ็คเอนด์ ฐานข้อมูล หรือการเข้าสู่ระบบเฉพาะในกรณีที่คุณถาม
- "สร้างแอปแบบฟูลสแตก" ก่อนอื่น เอเจนต์จะถามคำถามสั้นๆ หนึ่งคำถามเกี่ยวกับภาษาแบ็คเอนด์ ฐานข้อมูล การเข้าสู่ระบบ และตำแหน่งที่รัน โดยมีค่าเริ่มต้นที่แนะนำ จากนั้นจึงสร้างคำถามทั้งหมดด้วยข้อมูลเริ่มต้นและทดสอบโฟลว์ทั้งหมด
- "สร้างโปรแกรม Windows/ZYRAXON OS/macOS/Android" มีการเขียนซอร์ส เพิ่มเวิร์กโฟลว์บิวด์ พุชและสร้างในระบบคลาวด์ด้วยการดำเนินการ GitHub และคุณจะได้รับลิงก์ดาวน์โหลดจริง

## เครื่องมือ
- `edit_file` และ `write_file`: เขียนไฟล์จริง (โค้ดสมบูรณ์ ไม่เคย stubs) `code_box` แสดงสดพวกเขา
- `preview` (ปลอดภัย): เบราว์เซอร์จริงในตัว การดำเนินการ: เปิด (ลิงก์ `localhost:PORT` หรือไฟล์), โหลดซ้ำ, ย้อนกลับ, ไปข้างหน้า, ภาพหน้าจอ, เลื่อน, คลิก, พิมพ์, อ่านข้อความหน้า, ข้อผิดพลาดของคอนโซล, การประเมิน ตัวแทนดูงานของตัวเองก่อนที่จะบอกว่าเสร็จสิ้น
- `serve_local` (ระบบ): เริ่มต้นเว็บเซิร์ฟเวอร์บนโทรศัพท์สำหรับโฟลเดอร์และส่งกลับที่อยู่ LAN ที่อุปกรณ์อื่น ๆ บน Wi-Fi ของคุณสามารถเปิดได้
- `publish_website` (ระบบ): ให้บริการไซต์บนพอร์ตสาธารณะจากโทรศัพท์ `publish_cloudflare` (ระบบ): วางไซต์บนอินเทอร์เน็ตโดยไม่มีบัญชีผ่านอุโมงค์ Cloudflare และส่งคืนลิงก์ https สาธารณะ `publish_github` (ระบบ): เผยแพร่โครงการไปยังพื้นที่เก็บข้อมูล GitHub (หน้า) ด้วยโทเค็นของคุณ
- `git` (ระบบ): โคลน, เริ่มต้น, สถานะ, เพิ่ม, กระทำ, พุช, ดึง, แยก, ชำระเงิน, บันทึก, แตกต่างกับโทเค็นที่คุณบันทึกไว้ `github_pr` (ระบบ): สร้าง แสดงรายการ รวม และแสดงความคิดเห็นในคำขอดึง `github_actions` (ระบบ): แสดงรายการเวิร์กโฟลว์ เรียกใช้ ดำเนินการสำรวจความคิดเห็น และอ่านบันทึก ดังนั้นบิลด์จึงทำงานในระบบคลาวด์จากโทรศัพท์
- `build_app` (ระบบ): สร้างโปรเจ็กต์นี้ด้วย Gradle บนโทรศัพท์และติดตั้งผลลัพธ์
- `files_panel`, `todo_write`: ไฟล์เบราว์เซอร์และบอร์ดงาน

## กฎคุณภาพที่ตัวแทนปฏิบัติตาม
เค้าโครงที่สมบูรณ์ การออกแบบที่ตอบสนอง JavaScript ที่ใช้งานได้ แอนิเมชั่น สีและแบบอักษรที่สอดคล้องกัน (มืดและสว่างตรงที่พอดี) ไม่ใช่เทมเพลตทั่วไป โดยปกติหน้า Landing Page จะมีขนาด 300–900 บรรทัด สิ่งที่ยิ่งใหญ่กว่ามากขึ้น

## ถ้ามีอะไรดูพัง
กดแก้ไขในหน้าตัวอย่างหรือแจ้งเจ้าหน้าที่ โดยจะอ่านคอนโซล แก้ไขสาเหตุ เปิดหน้าใหม่ และตรวจสอบอีกครั้ง
