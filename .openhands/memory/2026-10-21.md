## ZYRAXON session — APK + desktop/STT work

### Provider (zyraxonai.lovable.app) — measured facts
- 10 models. Modalities: apex/pulse/neural=text; matrix/codex/quantum=text+image; titan=text+image+video;
  visionary=+pdf; cyber/genesis=text+image+audio+video.
- `/audio/transcriptions` -> **404**. Chat with `input_audio` (bare b64, data-url, audio_url, mpeg/bare format)
  -> always `audio_tokens: 0`; model says "no audio attached". **Audio input does NOT work upstream.**
- `image_url` data URLs DO work (verified: 1x1 red png -> "লাল").
- Direct requests to the provider from a non-browser UA -> Cloudflare **403 error 1010**. Must go through our proxy.
- No API key needed.

### Whisper / STT (real, verified)
- `faster-whisper` 1.2.1 + `av` 19.0.2 + numpy. PyAV's `av.open()` rejects `metadata_errors=`
  that faster-whisper passes -> decode manually with AudioResampler to 16k mono fltp, pass numpy array.
- Model size matters: `small` on Bangla gives GARBAGE (Telugu/Devanagari glyphs). `base` and `tiny`
  give accurate **romanised transliteration** ("Amar Gopun Kodh Holo Beguni Satash" for
  "আমার গোপন কোড হলো বেগুনি সাতাশ"). Default = `base`.
- Model load ~40s -> `server/stt.py --serve` is a warm line-JSON worker; server keeps it alive.
- Romanised output would make `TTS.langOf()` guess English and lock sessionLang to English ->
  `agent.js` now prefers `STT._srvLang` (language the recogniser reported) when present.
- transformers.js Whisper in Node did NOT work: needs a Float32Array, no mp3 decoding (returned "yon yon yon").
  Use faster-whisper instead.

### Android build
- `android/build.sh` (6 steps, no Gradle). Real compile error fixed: `AccessibilityBridge.resolveApp`
  called `o.put()` inside a catch block — org.json's put declares checked `JSONException`.
  Fixed with `try{o.put(...)}catch(JSONException ignored){}` + added the import.
- APK 49MB at android/zyraxon.apk. Assets staged from public/.

  Allow sheet and awaits a click. Fix: start the call, click `#sheet-allow`, then await.

### Shell gotcha (cost a round of bogus failures)
Background jobs written as `cd X && nohup python3 test/y.py &` inherit the *shell's*
CWD. Launching from `/tmp/macz` made python look for `/tmp/macz/test/y.py` ->
"can't open file". Always `pwd` first, and prefer absolute paths in nohup'd runs.
