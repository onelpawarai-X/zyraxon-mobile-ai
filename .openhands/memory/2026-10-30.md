### Gotchas worth remembering
- **The app has its own package-private `BuildConfig`** (`ai.zyraxon.assistant.BuildConfig`)
  that **shadows the generated one**, and it has no `VERSION_NAME`. Referencing
  `BuildConfig.VERSION_NAME` fails with "package-private in file". Read the version
  from `PackageManager.getPackageInfo(...).versionName` instead — that is also the
  honest answer for an update decision.
- `org.json.JSONObject` is **not mocked** in plain JVM unit tests; the parse tests
  need `@RunWith(RobolectricTestRunner::class)`.
- `assembleRelease --offline` fails on `lintVitalAnalyzeRelease` (needs
  `material-icons-core-desktop`, not in the offline cache). Build with
  `-x lintVitalRelease -x lintVitalAnalyzeRelease`; a real CI build with network is fine.
- The APK is ~146 MB (on-device LLM bundles), so asset upload is slow but works.

### Signing key
The old release key (`my-upload-key.jks`, alias `upload`, pw `zyraxon2026`) was lost
with the ephemeral workspace and is unrecoverable. New key `zyraxon-release-v2.jks`

## The mic "off/on off/on" complaint — the real cause (v6.7.1)
Not the toggle. `SpeechRecognizer` ends a session constantly and reports every
ending through `onError` (NO_MATCH=7, SPEECH_TIMEOUT=6, RECOGNIZER_BUSY=8,
NETWORK=2, SERVER_DISCONNECTED=11). The listener set `_isListening=false` for
ALL of them, so the indicator blinked many times a minute. Fix:
`voice/RecognizerError.kt` — transient codes keep the ear open, only
INSUFFICIENT_PERMISSIONS(9)/LANGUAGE_* close it and back off. 7 tests.
General lesson: **when a user says a hardware toggle "keeps switching", look at
what writes the state flag, not the toggle handler.** The off/on writes were in
the error callback.

## v6.12.0 — Linux userland shipped in the APK (PR #13)

**The finding that explains the whole session**: the latest *published* release is
**v6.9.0**. Every voice fix the user kept asking for was written in **v6.10.0** and
**v6.11.0** and neither was ever released. So "the mic churns / only a female voice /
the model's own speech-to-speech does nothing / my settings reset" were all fixed in
code the phone never received. **Check the latest release tag, not just the branch,
before debugging a reported symptom** — `curl .../releases?per_page=1`.

### LinuxRuntime: the four things that actually matter
1. **There is no `ar` in the bundled busybox.** The Kotlin `ar` reader is not a
   nicety; without it no `.deb` can be opened at all.
2. **Layout.** The bootstrap archive *is* the prefix (`bin/`, `lib/`, `SYMLINKS.txt`
   at its root) so it unpacks into `rootfs/usr`. A `.deb` payload already sits at
   `data/data/<pkg>/files/usr/...` so it unpacks into `rootfs`. Get this backwards
   and you get `usr/usr`.
3. **The payload is not relocatable by itself.** 337 ELF binaries carry
   `RUNPATH=/data/data/<upstream>/files/usr/lib` and 113 scripts name that path in
   their shebang. `proot` is what makes a tree at `/data/local/tmp/...` run: present
   the real tree at the path the payload was built for. `LD_LIBRARY_PATH` is only for
   `proot` itself, which runs before the translation exists.
4. **Do not write that path in the source.** The user's hard rule is zero upstream
   traces. `derivePrefix()` reads it back out of the payload's own `SYMLINKS.txt`
   (absolute targets all share `.../usr`), so the source names nothing and the tree
   stays relocatable. `isInstalled` also requires `SYMLINKS.txt`, so a half-copy
   reads as not installed.

### Verify an Android-only install without an emulator
This container has **no KVM and no system images**, so `avdmanager`/`emulator` are
dead ends. What works: replay the exact install algorithm in Python against the real
assets — unzip the bootstrap, follow `SYMLINKS.txt`, walk each `.deb` and merge the
`files/` subtree — then assert bash/apt/dpkg/proot/python/node/git/clang all land.
67 packages / 17,363 files for both ABIs. That is a real check of the logic.

### The keystore trap — verify the *published* APK's cert
Memory said the canonical key was `my-upload-key.jks` (cert `6dcfa05e…`). That file is
**gone**, so the default `KEYSTORE_PATH` fails outright. The truth came from downloading
the published **v6.9.0** APK and running `apksigner verify --print-certs` on it: it is
signed with **`5a03b61c…`**, which is exactly `zyraxon-release-v2.jks`. So v2 is canonical
and every future update must use it. **A release build must prove its cert matches the
last published APK, or the phone will refuse the update.** Recipe:
```
curl -sL -o prev.apk <last release apk url>
apksigner verify --print-certs prev.apk | grep SHA-256
apksigner verify --print-certs app-release.apk | grep SHA-256   # must be equal
```
Build env that works:
`KEYSTORE_PATH=$PWD/zyraxon-release-v2.jks STORE_PASSWORD=zyraxon2026 KEY_PASSWORD=zyraxon2026`
plus `JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64 ANDROID_HOME=/opt/android-sdk
GRADLE_USER_HOME=/tmp/gradle-home`, then
`/opt/gradle-dist/gradle-9.3.1/bin/gradle :app:assembleRelease -x lintVitalRelease -x lintVitalAnalyzeRelease --offline`
(~2m45s; the APK lands at `app/build/outputs/apk/release/app-release.apk`, ~434 MB).

### Real bug found while releasing
The APK declares four ABIs (`arm64-v8a armeabi-v7a x86 x86_64`) but only two payloads are
vendored (`aarch64`, `x86_64`). `assetDir()` mapped the device's *first* ABI to a folder
unconditionally, so a phone listing `armeabi-v7a` first was sent to an absent `linux/arm`
and the install died with a bare "no packages found". Fixed: walk the device's ABIs in
order and return the first folder that really holds `.deb`s; `arch()` returns null for an
unrecognised ABI. Pure `pickAssetDir(abis, exists)` so it is unit-tested. 3 new tests.

## v6.13.3 — i18n of the runtime strings, and the release-description cleanup

**The i18n gap (real bug).** The tables in `assets/i18n` only ever saw strings
inside the `ui` package. A lot of visible text is produced elsewhere —
`ZyraxonAiEngine` (model descriptions), `ZyraxonViewModel` (persona greetings,
GitHub token status, update errors), `ZyraxonModels` (tab/animation names),
`ProviderCatalog` (labels). Those were plain Bengali literals, so they stayed
Bengali in every language. Wrapped in `t(...)`; tables 331 → 409 keys.

**`tools/translate_missing.py` is the tool for topping up.** It reads
`tools/runtime_keys.json` and only translates the missing keys, appending to
every table. Run it after adding keys. It prints `files 60 min 409 max 409`.
Caveat: it is a mechanical MT — it injected **zero-width spaces** into some
values (`Cyber \u200b\u200bNeon Grid`) and read some labels too literally
(`টাস্ক` → "the task", `দার্শনিক` → "the philosopher", `পিংক লিভিং ওরা` →
"They are Pink Living"). Always audit the English table by hand after a run;
