## In-app auto-update (v6.5.0, 2026-10-30)

The user asked for a Settings **"⬆️ আপডেট"** button that scans the latest GitHub
release, plus a launch banner, and for all old tags/releases to be wiped first.
Built and shipped in one session.

- `update/Updater.kt` — the whole feature: `Version` (numeric compare, so 6.10.0 >
  6.9.0; text compare would have stranded everyone), `UpdateRelease`/`ReleaseAsset`,
  `UpdateState` sealed class, release scan, streamed download with progress, in-place
  install, install-permission handling.
- **Install is in place, not a second app**: `PackageInstaller` + `SESSION_COMMIT`
  intent, same package name and key, so Android replaces the installed app and
  chats/memories/settings survive. `REQUEST_INSTALL_PACKAGES` and the FileProvider
  were already in the manifest.
- `update/UpdateInstallReceiver.kt` reports install failures instead of a silent no-op.
- UI: `UpdatePane` in `SettingsSheet` (tab `"updates"`), `UpdateBanner` in
  `ZyraxonApp` (closable; a dismissed update is offered again next launch).
- Version badge now reads the **real** installed version via
  `Updater.installedVersionName(context)`.

### Gotchas worth remembering
- **The app has its own package-private `BuildConfig`** (`ai.zyraxon.assistant.BuildConfig`)
  that **shadows the generated one**, and it has no `VERSION_NAME`. Referencing
  `BuildConfig.VERSION_NAME` fails with "package-private in file". Read the version
  from `PackageManager.getPackageInfo(...).versionName` instead — that is also the
  honest answer for an update decision.
- `org.json.JSONObject` is **not mocked** in plain JVM unit tests; the parse tests
  need `@RunWith(RobolectricTestRunner::class)`.
- `assembleRelease --offline` fails on `lintVitalAnalyzeRelease` (needs
  `material-icons-core-desktop`, not in the offline cache). Build with
  `-x lintVitalRelease -x lintVitalAnalyzeRelease`; a real CI build with network is fine.
- The APK is ~146 MB (on-device LLM bundles), so asset upload is slow but works.

### Signing key
The old release key (`my-upload-key.jks`, alias `upload`, pw `zyraxon2026`) was lost
with the ephemeral workspace and is unrecoverable. New key `zyraxon-release-v2.jks`
(alias `upload`, 2048-bit RSA, cert SHA-256 `5a03b61cb2881acac6292272fbd75012203796cfa93886402955ad2e7d31c6fd`)
is stored in GitHub Actions secrets: `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`,
`ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. **Consequence:** installing v6.5.0 over an
older build needs one uninstall; every update after that is in place.

All old tags/releases deleted (v6.0.0, v6.1.0, v6.2.0, v6.4.0). Single release now:
**v6.5.0** (id 428853097), assets `ZYRAXON-v6.5.0.apk` + `.sha256`. PRs #4 (feature)

## Terminal + git, and the answer to "how does it work?" (evening)
Built the Terminal tab and `git clone` (PR #6). Traps, so they are not re-learned:
- busybox chooses its applet from `argv[0]`'s basename → `libbusybox.so` gives
  "applet not found"; symlink it as `busybox`. Applet farm must be **internal**
  storage (external is FUSE, no symlinks).
- JGit 5.x is `java.nio.file` (API 26+), minSdk is 24 → **core-library desugaring**
  (`desugar_jdk_libs_nio:2.1.5`, `isCoreLibraryDesugaringEnabled = true`) or it
  crashes on old phones. Proof: `strings classes*.dex | grep -c 'j$/nio/file'` → 395.
- Robolectric native runtime races under parallel test forks → `maxParallelForks = 1`.
- `cd ~/sub/dir` was resolved as an absolute path and silently fell back to home.
- README test table had drifted; regenerate from `app/build/test-results/*.xml`.

The user's question was: "there is a new app in there — with this command line can I
run every kind of command, so everything can be done? how does it work?" Answer given:
yes for everything inside the app's own sandbox (no root), git works via JGit, and the
AI and the user share one shell. Explained in Bengali in the final reply.

## minSdk 21 (Android 5.0) — v6.7.0, 2026-10-30
Floor 24 → 21. Only two things held it: Shizuku (AAR minSdk 23) and androidx.core
1.18 (minSdk 23). Fix = Shizuku 13.1.5→12.2.0, core-ktx 1.18.0→1.13.1, plus
`tools:overrideLibrary` so the AAR's own minSdk can't raise the app's.
API-21 lint (`NewApi`) fixes that were needed, all real:
- `Context.checkSelfPermission` → `ContextCompat.checkSelfPermission`
- `KeyguardManager.isDeviceSecure` → `isKeyguardSecure` below API 23
- `AudioTrack.Builder` → the `AudioTrack` constructor below API 23
- `Process.waitFor(long, TimeUnit)` is API 26 → poll `exitValue()` instead
- `Activity.requestPermissions` → `ActivityCompat.requestPermissions`
- `Settings.canDrawOverlays` → treat as allowed below API 23
- `canRequestPackageInstalls` → treat as allowed below API 26
Manifest `PermissionImpliesUnsupportedChromeOsHardware` needs
`<uses-feature ... required="false">` for camera and location.
**Real bug found:** the manifest registered `.update.UpdateInstallReceiver`, but
namespace is `com.zyraxon.assistant` while the class package is
`ai.zyraxon.assistant.update` — the receiver never existed, so in-app update
results were never delivered. Register components with the FULL class name.

## The mic "off/on off/on" complaint — the real cause (v6.7.1)
Not the toggle. `SpeechRecognizer` ends a session constantly and reports every
ending through `onError` (NO_MATCH=7, SPEECH_TIMEOUT=6, RECOGNIZER_BUSY=8,
NETWORK=2, SERVER_DISCONNECTED=11). The listener set `_isListening=false` for
ALL of them, so the indicator blinked many times a minute. Fix:
`voice/RecognizerError.kt` — transient codes keep the ear open, only
INSUFFICIENT_PERMISSIONS(9)/LANGUAGE_* close it and back off. 7 tests.
General lesson: **when a user says a hardware toggle "keeps switching", look at
what writes the state flag, not the toggle handler.** The off/on writes were in
the error callback.

## GitHub release mechanics on this repo (needed every release)
- The `GITHUB_TOKEN` env var belongs to user `zyraxon-X`, who is NOT a
  collaborator → `POST /pulls` fails 422 "must be a collaborator".
  **The owner token is inside the git remote URL**; extract it:
  `git remote get-url origin | sed -E 's#https://[^:]+:([^@]+)@.*#\1#'`
  and use that for create/merge/upload.
- `git tag -a` fails with "Committer identity unknown" → always pass
  `-c user.name=openhands -c user.email=openhands@all-hands.dev`.
- Upload assets to `https://uploads.github.com/repos/<o>/<r>/releases/<id>/assets?name=<n>`.
- `unzip` is NOT installed; read APK dex with python `zipfile` instead.
- aapt2 lives at `/opt/android-sdk/build-tools/*/aapt2`.
