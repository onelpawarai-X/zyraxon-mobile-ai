# 2026-10-20 — ZYRAXON mobile AI

## Localization was dead code (fixed)
The 60-language tables in `app/src/main/assets/i18n/*.json` and the `Loc` object
existed, but **nothing in the UI read them** — every string was a hard-coded
Bengali literal, so the tables were dead weight. Finished the job:

- `tools/localize_ui.py` had two real bugs that blocked it:
  1. `tokenize()` is defined in `tools/translate_ui.py`, not `kotlin_strings.py`.
  2. Captured interpolations kept their leading `$` (`$file.relative`), producing
     `t("…", $file.relative)` which does not compile. Strip `$` and unwrap `${…}`.
- Rewrote 246 literals across 7 UI files through `t()`.
- **`t()` must be a plain function, not `@Composable`.** A composable cannot be
  called from `remember { }` blocks or `onClick = { }` lambdas — that produced
  ~30 `@Composable invocations can only happen from the context of a @Composable
  function` errors. Language changes are propagated by keying the app root on the
  language state (`key(language)` in `MainActivity.setContent`), not by a
  CompositionLocal, because those same blocks capture the value once.
- Language picker lives in the Settings sheet. It must be a plain scrolling
  `Column`, **not** a `LazyColumn`: the sheet content already has
  `verticalScroll`, and a lazy list there is measured with infinite height and
  crashes.
- Choice persisted in `SharedPreferences("zyraxon_ui")`, restored before first frame.
- Tests: `LocalizationTest` (8) reads the real assets. Total **118 tests, 0 failures**.
