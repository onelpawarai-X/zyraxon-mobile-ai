## Session 2 — persistence bug + fastest-model default + screenshot gallery

### Root cause of "history doesn't come back after reload" (misdiagnosed for a while)
Two separate bugs stacked:
1. **`/api/model-health` blocked boot for 12s.** `App.boot()` awaited
   `loadModels()`, which awaited the health probe (probes all 10 models, ~12s
   worst case). Chat restore ran *after* that, so on a quick reload the restored
   messages never appeared before the user/test looked. Fixed by splitting
   `refreshHealth()` out of `loadModels()`: first paint uses the static
   FAST_INDEX order, health re-sorts the menu in the background.
2. **Service worker was cache-first**, so the browser kept serving old JS
   forever — a fix appeared not to work on reload. `public/sw.js` is now
   **network-first** (cache only as offline fallback), and the SW is not
   registered at all inside the APK (`!global.ZY.Native.app`), where assets are
   already local.

Lesson: when a change "doesn't take effect" here, first check
`curl http://127.0.0.1:12000/js/app.js | grep <new-symbol>` and the SW cache —
before instrumenting the JS.

## Home-screen transcript bug (user's "চ্যাট বক্স এত বড় কেন? আমি কিছু বললে চ্যাট বক্সে উঠে না")
Root cause was architectural, not CSS: the composer and the whole transcript live
inside `#console`, which is `hidden` on load (`console.css: .console{position:fixed;inset:0;z-index:60}`).
So speaking to the orb wrote into a detached/zero-size element — `.composer` measured
0x0 on the home screen, and `#input` was never visible (this is also why Playwright
`fill("#input")` timed out). Fix: added a real home-screen feed (`#home-feed`/`#hf-list`)
with `UI.feed(who, text, {key, replace})` + `UI.feedEnd()` + `UI.feedNote()`.
`streamToken` mirrors the streaming text into it with `replace:true`; `submit()` posts
the user turn with a per-turn key (`'me:'+Date.now()`) so turns don't merge.
UI facts: home has room for orb 297px + feed 226px in a 412x915 viewport, no overflow.

## Play Protect / special permissions
`WRITE_SETTINGS` and `PACKAGE_USAGE_STATS` added to the manifest. `WRITE_SETTINGS`
cannot be granted by a runtime dialog and `checkSelfPermission` always denies it —
`permissionState("write-settings")` must use `Settings.System.canWrite(this)`.
`playProtect(off)` writes `package_verifier_enable`, `verifier_verify_adb_installs`,
`package_verifier_user_consent` via `Settings.Global`; falls back to opening the
Play Store app page. New JS permission kinds: `write-settings`, `play-protect`.
