# 2026-10-23 — netFetch shape bug, publish_website regression, SDK reset

## The bug that mattered (found by probing, not by the suite)
`netFetch` (src/web/tools.ts) returned the browser's raw `Response` on the
non-bridge path, while every caller expects the native bridge shape
`{ ok, status, headers, text }` and reads `.text` directly. A `Response.text` is a
**function**, so `r.text != null` was true and callers used the function *itself*
as the body. `JSON.parse("function text() { [native code] }")` always failed.

Blast radius — six call sites, all silently broken on web/desktop (and the bridge
path was fine, which is why it hid): `read_url`, `web_search` (DDG), `http_request`,
`download_file`, GitHub `gh()` and GitHub pages verification. Symptoms were mild
and looked like provider flakiness: `github_account` returned `ok:true` with
`login: undefined` and `repos: []`; wikipedia search always fell through to
"no results" (it used `r.json ? r.json() : await r.json()`, so `j.query` was
`undefined` — it never awaited the promise).

Fixes:
1. Normalise inside `netFetch` itself — the non-bridge path now returns the same
   `{ ok, status, headers, text, contentType, bytes, viaBridge:false, json() }`
   shape as the bridge. One fix repaired all six callers.
2. `json()` must return a **Promise** on BOTH paths (bridge + browser): callers do
   `await r.json()` and some chain `.catch()`. The first fix made `json()` sync,
   which broke `publish_website` with `TypeError: r.json(...).catch is not a
   function` — a regression I introduced and then caught by probing again.
3. Remaining `r.text != null ? r.text : await r.text()` sites in github.ts/tools.ts
   rewritten to `typeof r.text === 'function' ? await r.text() : r.text`.

Lesson: a helper that has two backends (bridge vs fetch) must return ONE shape.
And when a fix changes a helper's contract, grep every caller for `await`/`.catch`.

## The second bug: an all-`done` todo board with no work (the user's complaint)
The continuation loop in `Agent.send` only forced another round when a todo was
still `pending`/`in_progress`. If the model wrote the board and marked every row
`done` in the same turn, `open.length === 0`, the loop broke, and it produced a
final answer having run **no real tool at all** — and because `todo_write` is in
`MUTATING`, the loop even believed something had happened. That is exactly
"সব টুডু done কিন্তু কিছুই হয়নি".

Fix in `src/web/agent.ts`:
- `todo_write` results are skipped in the bookkeeping loop (`todoTouched = true`,
  `continue`) — bookkeeping is not work.
- New `workDone` flag: true once any *other* tool succeeds.
- New nudge (bounded, `nudges < 2`): when `todos.length && todoTouched &&
  !workDone` and the model stops with no tool calls, refuse the answer and demand
  a real call. Guarded by `todoTouched` so a plain conversation whose *previous*
  turn left todos in the store is not punished.

Test `test/e2e.mjs` #35 drives this with a scripted model: round 1 `todo_write`
(all done) → round 2 tries to answer with no tools → asserts a nudge fired
(`demanded >= 1`), the loop kept going (`rounds >= 3`) and real work ran.
Gotcha while writing it: the template literal's inner `//` comments must not
contain a backtick, and the previous real turn may still be streaming, so the
test calls `A.stop()` and waits for `Agent.busy` to clear first.

## e2e additions (test/e2e.mjs, now 35 checks, all pass)
- "words spoken mid-task join the running turn, not a new one" — inject a sentence
  while `Agent.busy`; assert it reaches the same turn. Use `window.ZY.Agent.busy`
  as the busy signal, NOT the `#btn-stop` visibility (it lags).
- "a real network read returns the real body, not a stub" — `read_url` on
  `https://api.github.com/zen`; fails if the body contains "native code".
- Publish check now reads `window.ZY.store.get('lastSite')` first, then a
  `/sites/<id>/` URL from the tool log. Any random link proved nothing.

## Environment reset (container restart mid-session)
`$HOME` was wiped: Android SDK, JDK, `zip`, and `~/.android/debug.keystore` all
gone. Re-provisioned in this order:
- `sudo apt-get install -y openjdk-21-jdk-headless unzip zip`
- cmdline-tools zip from `dl.google.com/android/repository/commandlinetools-linux-11076708_latest.zip`,
  unpack to `$HOME/android-sdk/cmdline-tools/latest`, then
  `sdkmanager --sdk_root=$HOME/android-sdk --licenses` and install
  `platform-tools platforms;android-34 build-tools;36.0.0`
- `keytool -genkeypair ... -keystore $HOME/.android/debug.keystore` (storepass/keypass
  `android`, alias `androiddebugkey`, dname CN=Android Debug,O=Android,C=US)
Trap: a backgrounded `apt-get install` that gets stopped (state `T`) keeps the dpkg
lock forever; kill the exact PIDs, don't `wait`.

APK rebuilt and signed: `android/zyraxon.apk` 22MB, versionCode 190006,
versionName 19.0.6. Verified the fixed bundles are really inside it
(`assets/js/tools.js` contains `Promise.resolve(JSON.parse(text))` and
`typeof r.text === "function"`; `assets/js/github.js` has 2 of the latter;
zero "native code").
