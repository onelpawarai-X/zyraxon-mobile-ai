# 2026-10-31 — the multi-step engine fix and the restored live-voice pane

## The real cause of "একটা কাজ করার পরে পরের ধাপে যায় না"
`ZyraxonAiEngine.streamAiResponse` captures the fresh screen after a screen action
and injects it back — but the guard was
`if (parsed.any { isScreenTool(it.second) || it.second == "open_app" })`.
**`youtube_play` and `launch_url` were not in that condition.** So "ইউটিউবে গান
চালাও" opened the results and stopped: the model never received the results screen,
so it could not tap the first video. A system-prompt rule cannot fix this — the
information never reached the model. Fix: a new `SCREEN_CHANGING_TOOLS` set
(`open_app`, `youtube_play`, `launch_url`, `open_settings`, `call_dial`,
`channel_post`, `device_lock`) used in that guard.

## Engine-level continuation (the "system prompt only gives detection" point)
The user is right that the prompt only detects; the *turn* is ended by the engine
when the model returns text with no tool call. So `ContinuationPolicy` (pure,
tested) is consulted before the turn ends: a failure report ("পারলাম না",
"লেখা যায়নি", "could not"), a bare promise ("করছি", "খুলছি", "i will"), or a silent
stop right after `lastActionWasScreenChange` does **not** end the turn — the model
is nudged (max 4 times) to take the next step itself. `nudges` +
`lastActionWasScreenChange` are locals in the loop; the flag is cleared *before*
this round's calls run, so the read at the next "no tool call" check describes only
the round that just ran. (I first put the reset at the top of the loop and it was
wrong — it cleared the flag before the check could read it.)

## Tool-level refusal to fail
`ToolRegistry.writeFile` now catches a failed write and retries into the workspace
under a sanitised name, returning the real path in `note`. This is the second level
below the prompt: the tool itself refuses to end the job with "ফাইল লেখা যায়নি".
`resolve()` already mapped desktop-style paths ("/home/user/site") into the
workspace; this covers the remaining cases (bad chars, reserved names, a directory
where a file should be).

## Mic must stay open while the assistant speaks
`scheduleRestart` used to *defer* the reopen for the whole reply
(`if (speakingNow()) { wait-loop }`). That is why the user saw the mic off whenever
the assistant talked. Removed: the ear reopens on the normal floor+backoff, and the
assistant's own voice is dropped by text (`SttDecision`/`EchoMatcher`) instead. The
floor (`IDLE_RESTART_FLOOR_MS = 450`) and exponential backoff stay — they only space
out rebuilds, never close the ear. `speakingNow()` and `SPEAK_MAX_WAIT_MS` were left
unused and deleted.

## Live voice pane was deleted in v6.8.0
The `"live"` settings tab and its whole pane were gutted to a single "switched off"
line, leaving dead code (`liveVoiceEnabled` etc. still in the ViewModel). Restored
the tab and the full pane from `5270365^`. That is why "model's own speech-to-speech
does not work" — there was no UI to turn it on.
