# ZYRAXON — মোবাইল AI অ্যাসিস্ট্যান্ট

একটা সত্যিকারের বাংলা AI অ্যাসিস্ট্যান্ট — Android APK, Windows, macOS আর Linux — চার প্ল্যাটফর্মেই চলে।
ফেক নয়: রিয়েল স্ট্রিমিং, রিয়েল টুল কল, রিয়েল কমান্ড।

> This project was built and verified by an AI agent (OpenHands) on behalf of the user.

---

সবচেয়ে নতুন বিল্ড **[Releases](https://github.com/onelpawarai-X/zyraxon-mobile-ai/releases/latest)** পেজে আছে:

ডেস্কটপে আলাদা করে ইনস্টল করার মতো কিছু নেই — অ্যাপটা নিজেই একটা লোকাল সার্ভার, আর সেটা আপনার নিজের Chrome-এ খোলে।

## যা করতে পারে

### রিয়েল টুল কল
মডেল নিজে সিদ্ধান্ত নেয় কোন টুল লাগবে, সেটা চালায়, আউটপুট আবার তার কাছে ফেরত যায় — তারপর পরের ধাপে যায়।

| টুল | কাজ |
|---|---|
| `run_shell` | সত্যিকারের কমান্ড। Windows-এ PowerShell/cmd/pwsh, macOS-এ zsh/bash, Linux-এ bash, আর **ফোনে Android-এর নিজের `sh` স্যান্ডবক্স** |
| `open_app` | ফোনে/ডেস্কটপে অ্যাপ খোলা |
| `read_screen` | স্ক্রিনে কী আছে পড়া |
| `screen_shot` | স্ক্রিনশট নিয়ে মডেলকে দেখানো |
| `tap` / `swipe` / `type_text` | স্ক্রিনে সত্যিকারের টাচ/সোয়াইপ/টাইপ |
| `todo_write` | টাস্ক লিস্ট — কাজ শেষ না হওয়া পর্যন্ত থামে না |
| `publish_website` | সত্যিকারের ওয়েবসাইট বানিয়ে GitHub Pages-এ পাবলিশ |
| `read_url` | যেকোনো URL পড়া |
| `read_file` / `write_file` | ফাইল পড়া/লেখা |

### রিয়েল-টাইম স্ট্রিমিং
উত্তর আসে SSE (Server-Sent Events) দিয়ে — টোকেন আসতে আসতেই স্ক্রিনে, একবারে শেষে নয়।

### বাংলা ভয়েস — সব প্ল্যাটফর্মে
| প্ল্যাটফর্ম | STT (আপনার কথা) | TTS (তার কথা) |
|---|---|---|
| Android | ফোনের নিজের `SpeechRecognizer` | ফোনের নিজের `TextToSpeech` |
| Windows / macOS / Linux | Chrome/Edge-এর নিজের recogniser (ব্রিজ উইন্ডো) | Chrome/Edge-এর নিজের কণ্ঠ, না থাকলে সার্ভারের বাংলা TTS |

ওপেন-সোর্স Chromium-এ `webkitSpeechRecognition` থাকে কিন্তু পিছনের Google সার্ভিসটা থাকে না — তাই শুধু আসল Chrome বা Edge-এ ভয়েস কাজ করে, আর লঞ্চার নিজেই সেটা বেছে খোলে। কেউ না থাকলে টেক্সট-চ্যাট, টুল কল, কোড লেখা — সবই চলে, শুধু মাইক আর কণ্ঠ বন্ধ থাকে।

### চরিত্র
গার্লফ্রেন্ড, বয়ফ্রেন্ড আর সাধারণ বন্ধু — ইউজার বললেই সুইচ করে। লোকাল ডেটাবেসে সব মনে রাখে, ক্লাউড মুছে গেলেও।

### মডেল সিলেকশন
১১টা ZYRAXON মডেল, ইউজার নিজে বেছে নেয়।

## চালানো — Windows / macOS / Linux

শুধু Node (v20+) থাকলেই হবে। একটাই ফাইল:

```bash
node zyraxon.mjs
```

এটা শুধু **লোকাল হোস্টে** সার্ভার চালু করে — কিছুই কোথাও আপলোড হয় না, বাইরে থেকে কিছু আসে না। তারপর নিজেই Chrome/Edge খুঁজে একটা অ্যাপ-উইন্ডোতে অ্যাপটা খুলে দেয়, আর ওই উইন্ডোতেই মাইক আর কণ্ঠ সবচেয়ে ভালো কাজ করে। কোনো ইনস্টলার, কোনো Electron, কোনো বিল্ড — কিছুই লাগে না।

চাইলে Chrome ব্রাউজারের ভেতরেও সরাসরি একই ঠিকানা খুলতে পারেন:

```
http://localhost:12000
```

পোর্টগুলো এই ক্রমে চেষ্টা করা হয় — যেটা খালি, সেটাতেই চলে:
`12000 → 12001 → 12002 → 13000 → 13001 → 13002 → 14000 → 8080`

```bash
node zyraxon.mjs --port 13000   # অন্য পোর্ট
node zyraxon.mjs --no-open      # হেডলেস (সার্ভিস/কনটেইনার/CI)
node zyraxon.mjs --browser      # কোন ব্রাউজার ব্যবহার হবে দেখাও
```

পোর্ট ব্যস্ত থাকলে নিজেই পরের ফাঁকা পোর্টে চলে যায়; অ্যাপ আগেই চালু থাকলে দ্বিতীয় কপি না খুলে সেটাই খোলে।

> ভয়েসের জন্য আসল **Chrome** বা **Edge** দরকার — ওপেন-সোর্স Chromium-এ পিছনের Google স্পিচ সার্ভিস থাকে না। যদি এমন ব্রাউজারে অ্যাপটা খোলেন, অ্যাপ নিজেই বুঝে নিয়ে একটা ছোট ভয়েস-উইন্ডো খুলে দেয় (প্রথম ট্যাপেই) — ওখানেই মাইক আর কণ্ঠ চলে। ব্রাউজার একেবারেই না পেলেও টেক্সট-চ্যাট, টুল কল, কোড, publish — সব চলে।

### Android APK বিল্ড
Gradle লাগে না — শুধু Android SDK (aapt2 + javac + d8 + apksigner):
```bash
bash android/build.sh        # → android/zyraxon.apk
```
আগে যা লাগবে: **JDK 17+** (`javac`), `zip`, আর একটা Android SDK — `build-tools`
(36.0.0) আর `platforms/android-34` সহ। SDK-র জায়গা `ANDROID_HOME`-এ দিন
(ডিফল্ট `~/android-sdk`); লাইসেন্স `sdkmanager --licenses` দিয়ে একবার মেনে নিন।
ডিবাগ কীস্টোর না থাকলে `~/android/.debug.keystore` নিজেই বানিয়ে নেয়।

APK-তে ভয়েস ফোনের নিজের `SpeechRecognizer` + `TextToSpeech` দিয়ে চলে, ব্রাউজার লাগে না।
মার্কেটিং স্ক্রিনশট (`public/shots/`) আর Whisper ইঞ্জিন APK-তে ঢোকে না — ফোনে
দরকারও নেই, তাই বিল্ড হালকা থাকে (~২২MB)।

### ভার্সন বদলাতে হলে
ভার্সন পাঁচ জায়গায় থাকে — `package.json`, `desktop/package.json`,
`AndroidManifest.xml` (`versionName` **ও** `versionCode`), আর `BuildConfig.java`।
সবগুলো একসাথে বদলান, তারপর:
```bash
node test/versioncheck.mjs   # একটাও আলাদা থাকলে ফেল করবে
```
বিল্ড হওয়া APK থাকলে এই টেস্টটা তার ভিতরের ম্যানিফেস্ট পড়ে সেটাও যাচাই করে।
`versionCode` = ভার্সনের প্রতিটা অংশ দুই ডিজিটে (১৯.০.৬ → `190006`) — না বাড়লে
Android আপডেট ইনস্টল করতে রাজি হয় না।

## টেস্ট

```bash
node test/e2e.mjs        # ফুল end-to-end: UI, মডেল, SSE, টুল কল, টুডু, publish, চরিত্র
node test/bridgecheck.mjs # বাংলা ভয়েস ব্রিজ (মাইক → চ্যাট → কণ্ঠ)
node test/mediaperf.mjs  # ব্যাকগ্রাউন্ড ভিডিও: fps, ফ্রেম ড্রপ, CPU খরচ
node test/typing.mjs     # কম্পোজারে স্পেস/ট্যাব (বাংলা লেখা সহ)
node test/perfattr.mjs   # কোন লেয়ার কত ফ্রেম খায় — ভাষা নয়, কম্পোজিটর
```

পাঁচটাই আসল Chromium-এ আসল কোড চালায় — কোনো নকল নয়।

### ল্যাগ কি ভাষার জন্য? (মাপা উত্তর)

প্রশ্নটা প্রায়ই আসে: অ্যাপটা যদি নেটিভ Java-তে লেখা হতো, দ্রুত হতো? মেপে
দেখলে উত্তর — **না, ল্যাগ ভাষার কারণে নয়।** `test/perfattr.mjs` আসল
ব্রাউজারে ব্যাকগ্রাউন্ড ভিডিও, অ্যানিমেটেড ওরা আর গ্লাস-ব্লার আলাদা আলাদা
চালু/বন্ধ করে ফ্রেমের সময় মাপে, সাথে মেইন থ্রেডের long-task সময়ও:

```
layer                              fps    median   p95     main-thread
nothing (bare shell)                60    16.7ms   16.8ms  busy 0% (0 long)
+ background video                  60    16.7ms   16.8ms  busy 0% (0 long)
+ animated orb (shipping CSS)       60    16.7ms   16.8ms  busy 0% (0 long)
+ glass blur                        60    16.7ms   16.8ms  busy 0% (0 long)
all three (shipping state)          60    16.6ms   18.1ms  busy 0% (0 long)
```

মূল কথাটা শেষ কলামে: **মেইন থ্রেড ~০% ব্যস্ত, শূন্য long task।** অর্থাৎ
JavaScript-এর নিজের কোনো কাজ ফ্রেম খাচ্ছে না। ফ্রেমের খরচ পুরোটাই
কম্পোজিটরের (ভিডিও ডিকোড + ব্লারড লেয়ার র্যাস্টারাইজ) — নেটিভ অ্যাপও ঠিক
একই কম্পোজিটরের কাজই দিত, তাই Java-তে লিখলে কিছু বদলাত না।

সৎ একটা কথা: প্রথম কয়েকটা রানে ওরা-কে ১.১২–১.৬২x খরচ দেখাচ্ছিল, কিন্তু
সেটা পুনরুৎপাদনযোগ্য ছিল না — একটা কনফিগ একবার ৩৬fps, পরের চারবার ৬০fps।
একটা নমুনা (sample) এখানে প্রমাণ নয়। তাই টেস্টটা এখন ৫টি ইন্টারলিভড
নমুনার **মিডিয়ান** নেয়, আর কোনো লেয়ার বেয়ার শেলের ১.১৫x ছাড়ালে ব্যর্থ হয়।
যাচাই করা হয়েছে: ইচ্ছে করে ফুল-স্ক্রিন `blur(60px)` ঢুকিয়ে দিলে ১.৫৬x-এ
FAIL করে, সরিয়ে দিলে আবার PASS।

```bash
node test/perfattr.mjs        # সব লেয়ার মিলিয়ে ফ্রেম-খরচের হিসাব + গার্ড
```

### ব্যাকগ্রাউন্ড ভিডিও অপ্টিমাইজ

বান্ডল করা ক্লিপগুলো H.264 (Main profile, yuv420p), সর্বোচ্চ 1280px চওড়া।
মূল ফাইলগুলো VP8/VP9 ছিল — `nightlights` ছিল 3840x2160, `city` 1920x1080 — আর
ব্রাউজারে VP9-এর হার্ডওয়্যার ডিকোড প্রায়ই থাকে না, তাই প্রতিটি ফ্রেম CPU-তে
ডিকোড হতো। ডেস্কটপ শেলে যে ল্যাগ ছিল তার আসল কারণ ওটাই।

```bash
bash scripts/optimize-media.sh   # আবার এনকোড (ffmpeg দরকার)
node test/mediaperf.mjs          # যাচাই: কোনো ক্লিপ যেন আবার ভারী না হয়ে যায়
node test/mediaperf.mjs /path/new.mp4   # নতুন ক্লিপ যোগ করার আগে মেপে দেখুন
```

`test/mediaperf.mjs` রেজোলিউশন, সোর্স fps, ফ্রেম ড্রপ ও CPU বাজেট মেপে
ব্যর্থ হয় — তাই ভবিষ্যতে কোনো ভারী ভিডিও চুপিচুপি ঢুকে পড়তে পারবে না।
